# QA 基建 · 家庭出行计划

> 这里放测试的「规矩」，不是测试的「记录」。记录在 `cases/`（用例）、`tracking/`（状态）、`defects/`（缺陷）、`reports/`（报告）。

## 一、目录职责

| 目录                    | 内容                                                  | 谁写                      |
| ----------------------- | ----------------------------------------------------- | ------------------------- |
| `cases/`                | 用例文档，**唯一真实来源**。需求变了先改用例          | 测试                      |
| `tracking/执行追踪.csv` | 每条用例的状态（PASS/FAIL/BLOCKED/NOT RUN）+ 证据类型 | 测试，每轮执行后回填      |
| `defects/`              | 缺陷单，按日期一版                                    | 测试；研发回填修复 commit |
| `reports/`              | 每轮测试报告 + 门禁结论 + 探针截图                    | 测试                      |
| `probes/`               | 可重复运行的行为取证脚本（无头浏览器）                | 测试                      |
| `templates/`            | 用例 / 缺陷模板                                       | —                         |

**铁律一**：用例文档是权威来源，CSV 只记状态。两者冲突时以用例文档为准，回头修 CSV。
**铁律二**：缺陷没有编号复现步骤 = 没提。截图/日志/请求字节，三样至少给一样。
**铁律三**：`PASS` 必须写清证据类型（无头实测 / 静态审查 / 单测 / 历史证据）。静态审查不算运行通过，报告里要单独披露。

## 二、质量门禁（全绿才放行）

| 门禁         | 标准  | 说明                                       |
| ------------ | ----- | ------------------------------------------ |
| 执行率       | 100%  | `(PASS+FAIL) / 总用例数`。BLOCKED 不算执行 |
| 通过率       | ≥ 80% | `PASS / (PASS+FAIL)`                       |
| P0           | 归零  | 数据丢失、越权、核心链路中断               |
| P1           | 归零  | 主要功能不可用                             |
| 安全用例覆盖 | ≥ 90% | H 模块（越权、注入、隐私、加密）不得留白   |

不达标只有两种出口：修到达标，或产品书面确认范围裁剪并转 Backlog。**不接受「差不多能发」。**

## 四、用例写法（Google AAA）

```
准备（Arrange）：前置数据、账号、环境、初始状态
执行（Act）    ：具体点哪里、填什么、调什么
断言（Assert） ：可观测的预期结果（文案/数值/接口/状态）
```

要求：

- 三步缺一不可，**「测试思路」不收**。
- 断言必须可判定，禁止「显示正常」「体验良好」。
- 每条带优先级（P0–P3），P0 用例必须能在 10 分钟内跑完。
- 边界与异常单独成条：空值、超长、并发、断网、越权、重复提交。

## 五、缺陷分级与时限

| 级别 | 判据                                              | 时限     |
| ---- | ------------------------------------------------- | -------- |
| P0   | 数据丢失、越权/隐私泄露、核心链路中断、发版即事故 | 24h 内修 |
| P1   | 主要功能不可用或结果错误，绕行成本高              | 48h 内修 |
| P2   | 功能缺失或与需求不符，有替代路径                  | 本迭代修 |
| P3   | 体验、口径、展示问题                              | 排期修   |
| P4   | 文案、细节打磨                                    | 有空再修 |

**判定纪律**：代码注释里写明的「有意设计」不算缺陷，记「待产品确认」；脚本断言过期不算产品缺陷，记测试资产缺陷（TA-xxx）。
