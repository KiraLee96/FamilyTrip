## 4. 四个已知陷阱（提前说，省一次来回）

1. **只 restart 不 build** → 进程起来了，跑的还是旧 `dist`，自检仍是 4040/500。这是本轮卡住的头号原因。
2. **build 了但没 migrate deploy** → `finish` 仍 500（`access_level` 还是 `varchar(16)`），会误判成「代码没修好」。
3. **`.env` 没补媒体三件套** → 上传回 5008「媒体存储未配置」（服务本身正常，不会挂）。
4. **nginx 没加 `/media-files/` 两段或没 reload** → presign 拿到地址但上传 404 / 回读 404。
   判断：`curl -X POST https://api.familytripallinone.cn/media-files/upload` 无签名 → 应回 **JSON 403**；
   回 HTML 404 页 = nginx 没配；回 JSON 4040 = 后端版本没换。
5. `booking` / `itinerary_item` 的 `rate_source` 上挂着 CHECK 约束（`chk_bk_rate_by` / `chk_ii_rate_by`）。
   MySQL 8.0.46 允许带约束 `MODIFY`（只放宽宽度，既有行不会违约）；万一报错，
   按「`ALTER TABLE ... DROP CHECK` → MODIFY → 重新 ADD」处理，约束定义见 `20261013170000_b1_drift_fix`。

## 7. 只想本地测试？**不需要 commit**

`commit` 只有一个用途：让服务器 `git pull` 能拿到代码。本地跑的是你磁盘上的文件，跟 git 没关系。

本地三条路径，按你想验的东西选：

| 想验                                     | 命令                                                | 说明                                                                                                                      |
| ---------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **只点界面 / 验接口逻辑**（最快）        | `cd apps/server && DATABASE_URL= pnpm dev`          | `pnpm dev` = `tsx watch src/main.ts`，**直接跑源码**，不 build 也不 commit。`DATABASE_URL=` 置空 → 内存驱动，重启数据全丢 |
| **验列宽这根因**（唯一能复现 1406 的路） | 起 MySQL → `npx prisma migrate deploy` → `pnpm dev` | 见下方说明                                                                                                                |
| 验编译产物                               | `pnpm build && node dist/main.js`                   | 不 commit 也能跑，`dist` 是 gitignore 的                                                                                  |

### ⚠️ 本地现在很可能是另一个 500（不是本单那个 bug）

`.env` 里 `DATABASE_URL=mysql://root:***@localhost:3306/family_trip`，而本机 **3306 上没有 MySQL**
→ 驱动选择逻辑见到连接串就选 **prisma 驱动**（不会静默退回内存）→ 每个碰库的请求都：

```
{"code":5000,"message":"服务内部错误","data":null,"meta":{}}
日志：Can't reach database server at `localhost:3306`   （日志里 data driver: prisma）
```

所以本地联调要么把 MySQL 起起来，要么显式 `DATABASE_URL= pnpm dev` 走内存驱动。
（判定方法：启动日志第一行 `data driver:` 是 `prisma` 还是 `memory`。）

### 本地复现「列宽」根因的黄金路径（我这边做不了，你本地能做）

```bash
# ① 起 MySQL 后，先把库建到**旧状态**（不迁移，access_level 仍是 varchar(16)）
mysql -uroot -p family_trip -e "SHOW CREATE TABLE trip_member\G" | grep access_level
# ② 造一条过期行程 → 点「标记完成」或 curl finish → 期望：500（1406 Data too long）
# ③ 跑迁移
cd apps/server && npx prisma migrate deploy
# ④ 再点一次 → 期望：200，status=FINISHED
```

这一步能把我只能"静态推理"的根因变成真库实证。**不 commit 也完全能做** —— `migrate deploy` 读的是磁盘上的 `prisma/migrations/`。
