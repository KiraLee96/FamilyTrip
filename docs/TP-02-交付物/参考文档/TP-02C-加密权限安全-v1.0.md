## 一、组 C · 加密与密钥生命周期（7 项）

### C-1 存储格式升级（技术 M14 / B4）

```
[1B format_ver][1B key_ver][1B algo_id][12B IV][ct][16B tag]
```

| 字段         | 长度 | 说明                                |
| ------------ | ---- | ----------------------------------- |
| `format_ver` | 1B   | 存储格式版本，当前 `0x01`           |
| `key_ver`    | 1B   | 密钥版本，轮换递增                  |
| `algo_id`    | 1B   | 算法标识，当前 `0x01` = AES-256-GCM |
| `IV`         | 12B  | `crypto.randomBytes(12)`            |
| `ct`         | 变长 | 密文                                |
| `tag`        | 16B  | GCM 认证标签                        |

- 落库列：`booking.order_link_enc VARBINARY(2048)`（A22），**禁止静默截断**。

### C-2 AAD 绑定（技术 M14 / B4；第二 N-B3）

```
setAAD( format_ver ‖ key_ver ‖ algo_id ‖ recordId )
```

- `recordId` 为记录主键的稳定字节表示，**绑定后密文无法被平移/替换到另一条记录**；
- 解密时必须传入**完全相同**的 AAD，否则 GCM 校验失败；
- TP-03 复核重点：`recordId` 编码一致性（字节序 / 字符串化规则）。

### C-3 解密前长度校验（技术 M15 / B4）

```
if (field_length < 1 + 1 + 1 + 12 + 0 + 16) throw new DecryptFormatError();
```

- **禁止静默截断**；长度不足立即抛错并记录（脱敏后）告警；
- 与 A22 的 DB 容量上限形成双保险。

### C-4 IV 生成规则（技术 B4；第二 N-B3）

| 允许                     | 禁止                                                |
| ------------------------ | --------------------------------------------------- |
| `crypto.randomBytes(12)` | 时间戳、计数器、`Math.random()`、从 `recordId` 派生 |

- **同一记录重加密必须使用新 IV**（密钥轮换重加密时严禁复用）；
- TP-03 复核重点：CI 静态检查 IV 来源，禁止非 CSPRNG。

### C-5 DEK 拉取与缓存（第二 N-B3）

- 启动时从 KMS 拉取 DEK，本地缓存，**TTL ≤ 10 分钟**；
- 轮换事件**主动刷新**缓存，不等 TTL 过期；
- 生产环境**禁用 heapdump**（`--heapsnapshot-near-heap-limit` 关闭、禁 `kill -USR1`）；
- **密钥不进日志**（纳入 G6 脱敏白名单）。

### C-6 密钥退役三步（第二 N-B3）

```
① 转为只读（停止用该版本加密）→ ② 观察该 key_ver 数据量归零 → ③ 销毁
```

- 中间观察期长度由 TP-03 定；未归零**绝不销毁**；
- 归零判定：扫描全库该 `key_ver` 的密文计数为 0。

### C-7 同密钥加密调用数监控（第二 N-B3）

- 监控每把密钥的累计加密调用数，**上限 2³²**；
- 达到阈值（建议 90% 预警）**立即轮换**；
- GCM 的 IV 随机性假设在 2³² 次调用后需重新评估（生日界）。

## 二、组 D · 权限与安全（8 项）

### D1 权限判定按资源域分派（技术 M16 / B3）

```
PRIVATE 资源：仅走 owner_id = U OR managed_by = U，短路返回，不参与家庭/出行 OR 合并
```

- **PRIVATE 短路**是防越权的关键：私有资源绝不能被"我是家庭成员"这一维度放行；
- 逻辑：`isPrivate(resource) ? checkPrivate(U, res) : checkShared(U, res)`。

### D2 声明式 Policy（资源类型驱动，第二 N-B2）

```typescript
// 调用方只传资源 ID，不传维度
@RequireAccess(ResourceType.CHECKLIST_ITEM, AccessMode.READ)
async getItem(@Param('id') id: string) { ... }
```

- 维度（家庭 / 出行 / 私有 / 代管）由 Policy 内部**按资源类型自行推导**，调用方不参与；
- 消除"调用方传错维度导致越权"这一类漏洞。

### D3 权限缓存结构（第二 N-B2）

- 缓存键纳入**角色**（OWNER / MEMBER / LEADER）与 **access_level**（ACTIVE / HISTORICAL_READONLY）；
- 用 `Set` / `Map` 替代 `Array.includes`（O(1) 命中，且避免类型混淆）；
- 失效时机：成员变更 / 角色变更 / access_level 变更时精确失效相关键。

### D4 CI 强制标注（第二 N-B2）

- NestJS `Guard` + `@RequireAccess` 装饰器；
- **CI 检查：未标注 `@RequireAccess` 或 `@Public()` 的路由处理器 → 构建失败**；
- 白名单（如登录回调）必须显式 `@Public()`，不允许"忘记标注"通过。

### D5 越权访问私有资源统一 404（技术 M31 / T-3；**与 C2 协调**）

| 场景             | 响应                                                   |
| ---------------- | ------------------------------------------------------ |
| 访问他人私有资源 | **404**（不暴露存在性）                                |
| 列表接口         | 不得返回非本人私有项的 `owner_id` / `item_id` / `name` |
| Repository 过滤  | `WHERE owner_id = :uid OR managed_by = :uid`           |

**✅ 与 C2 的协调口径（2026-09-30 由 Kira 签认，正式生效）**

- **背景张力**：C2（设计）要求私人清单以「带锁占位」呈现，承载 E-11「无权限」提示位；
  D5（安全）要求越权访问统一 404、不暴露资源存在性。
- **签认解法（两层分治）**：

| 层                                             | 规则                                                                                                                     |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **单资源按 ID 直查**（`GET /{resource}/{id}`） | 越权 → **404**，与「资源不存在」响应体逐字节一致（D8）→ **防 ID 枚举**                                                   |
| **列表层**                                     | 对"有私有内容但当前用户无权限查看"的成员，返回**聚合占位**：`{ type: 'LOCKED_PRIVATE', ownerDisplayName: '<家庭昵称>' }` |

- **列表占位的三条硬约束**（实现与 TP-03 复核共同卡点）：
  1. **不逐条返回**：每位成员**最多 1 条**聚合占位，**不返回**私有项数量（避免条目数侧信道）；
  2. **不携带任何私有字段**：无 `owner_id` / `item_id` / `name` / 标题 / 内容 / 金额；
  3. **`ownerDisplayName` 白名单**：仅取自**家庭成员公开昵称**（家庭内本就全员可见），非私有资源字段。
- **前端渲染**：「这是 XX 的私人清单，仅本人可见」——`XX` = `ownerDisplayName`；占位可点击但只展示 E-11 提示。
- **结论**：存在性由**无信息占位**表达（满足 C2），ID 枚举由**单查 404** 阻断（满足 D5），二者不冲突。

### D6 权限查询含代管人（技术 B5）

```sql
WHERE `user_id` = :U OR `managed_by` = :U
```

- 修复虚拟成员代管人断链：虚拟成员（`is_virtual=1`）无真实 `user_id`，
  其代管人 `managed_by` 必须纳入权限判定；
- 与 A11 的 `managed_by` 列、A23 的 `chk_fm_virtual` 约束配套。

### D7 成员退出后私有内容归属不变（技术 M34 / T-6）

- 成员退出家庭后，其 `checklist_template` / `item` / `outfit` 的 `owner_id` **保持不变**；
- **不软删、不转移**（避免历史数据"送人"或"丢失"）；
- 访问控制：退出者失去家庭访问权，但内容归属记录保持完整，便于审计与恢复。

### D8 权限失败与资源不存在的响应体完全一致（技术 T-3）

- 两种情况返回**逐字节一致**的响应体与状态码（均 404 + 相同 body 结构）；
- 防止通过响应差异（状态码 / body / 响应时间）反推资源是否存在；
- TP-03 复核重点：响应时间侧信道（是否存在提前返回的时间差）。
