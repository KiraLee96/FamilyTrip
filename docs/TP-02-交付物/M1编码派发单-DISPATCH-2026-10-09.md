### 3.1 M2 · 加密字段适配层

**背景**：Prisma 6.19.3 从 MySQL 读回 `VARBINARY` 时返回**裸 `Uint8Array`**，不是 `Buffer`（无 `readUInt32BE` / `slice` 等方法）。

**唯一正确写法**：

```js
// ✅ 正确
const plain = decipher.update(toBuffer(rt), undefined, undefined);
```

```js
// ❌ 禁止：Buffer.isBuffer 对 Uint8Array 返回 false
const plain = decipher.update(rt, undefined, undefined);
```

**⚠️ 为什么最危险**：直接传 `Uint8Array` 给 crypto 层，**可能静默失败、不报错**。数据看起来是空的，排查成本极高。

**盲索引 4 条规则**：

| 规则                   | 说明                                                    |
| ---------------------- | ------------------------------------------------------- |
| 仅用于**等值检索**     | 不得用于范围查询、排序、模糊匹配                        |
| 计算式固定             | `sha256(低基数字段 + 主键)`，低基数字段必须**全部**参与 |
| 命中后**仍走完整鉴权** | 盲索引命中 ≠ 有权访问，必须继续走三级鉴权               |
| 不得单独建索引         | 必须与加密列在**同一事务**内写入                        |

**密文规范（v1.3 §4.7，不得改动）**：

```
[1B format_ver][1B key_ver][1B algo_id][12B IV][ciphertext][16B authTag]
└────── 加密头 = 15B ──────┘
1 + 1 + 1 + 12 = 15B
```

| 字段         | 长度 | 取值                                            |
| ------------ | ---- | ----------------------------------------------- |
| `format_ver` | 1B   | `0x01`（新格式；v0 为无头旧格式）               |
| `key_ver`    | 1B   | `users.dekVersion`（0–255）                     |
| `algo_id`    | 1B   | `0x01` = AES-256-GCM                            |
| `IV`         | 12B  | GCM 标准 96-bit nonce，**每记录唯一，严禁复用** |

**AAD**：`format_ver ‖ key_ver ‖ algo_id ‖ recordId`，其中 `recordId := "<表标识>:<主键>"`。
🔴 **禁止用裸主键** —— 两表主键同为 `123` 时裸主键会使 AAD 相同 → 搬运后 tag 校验通过 → **越权读取成功**。加表标识后 AAD 不符 → 认证失败拦下。

**容量公式**：`列容量 − 15 − 16`

| 列                             | 容量              | 明文上限               |
| ------------------------------ | ----------------- | ---------------------- |
| `order_link_enc`               | `VARBINARY(2048)` | ≤ 2000B（2017 留余量） |
| `order_no_enc` / `contact_enc` | `VARBINARY(1024)` | ≤ 950B（993 留余量）   |
| 盲索引                         | `VARBINARY(32)`   | `sha256` 摘要 32B      |

**长度校验**：`field_length >= 15 + len(ct) + 16`，反解明文 `len(pt) = field_length − 15 − 16`

**密钥**：KMS CMK 保护 per-user DEK。⛔ **Node.js 无法真正擦除密钥**（V8 GC 会搬移对象，`Buffer.fill(0)` 只尽力而为）。
