### P0-B HTTP 边界兜底：**采纳**（§3.2 建议）

实现与派发单建议的差异：**装在 `main.ts`（Express 全局 `json replacer`），而非 `http-adapter.controller.ts` 内联 `JSON.parse(JSON.stringify(...))`**。理由：

1. `app.set('json replacer', fn)` 覆盖**所有** `res.json()` 路径，包括 Nest 异常过滤器与未来新增出口；controller 内联只能守住那一个调用点；
2. controller 的现有契约是「除转发外无第二个分支」（access-gate 可机械校验），内联序列化会破坏该性质；
3. 语义等价： replacer 在 `JSON.stringify` 内部逐值回调，省一次全量 stringify+parse 的往返。

```typescript
// src/common/envelope/envelope.ts
export function bigintSafeReplacer(_key: string, value: unknown): unknown {
  if (typeof value !== 'bigint') return value;
  const asNumber = Number(value);
  return Number.isSafeInteger(asNumber) ? asNumber : value.toString();
}
// src/main.ts
http.set('json replacer', bigintSafeReplacer);
```

配套 8 个单测（`envelope.test.ts`）覆盖：number 安全整数、string 超出、非 bigint 原样、嵌套对象/数组、null。

## 7.5 §六 三点的决定

### 7.5.1 `version` 对外类型口径：**number**（未采纳「统一为 string」的初步建议）

| 维度        | 结论                                                                     |
| ----------- | ------------------------------------------------------------------------ |
| 客户端契约  | `apps/client/src/api/types.ts` 五处 `version: number`，**零改动**        |
| 驱动 parity | 内存驱动输出 number；若真库出 string 即制造口径分叉（本类缺陷的根源）    |
| 值域        | 乐观锁小计数器，永不超 2^53，无精度风险                                  |
| 回传        | `updateTripSchema` 的 `z.coerce.number()` 可接住（S6 实证 409 冲突路径） |
| 雪花 id     | `id` 等超大值由边界 replacer 输出 **string**，天然正确（S2 实证）        |

因此 `version` **故意不入白名单**，由边界 replacer 按 number 输出；白名单职责收窄为「标识类字段必须序列化为字符串」。envelope.ts 注释已写明该口径。

### 7.5.2 审计清单取舍：**只修 5 处真漏列，并把审计脚本升级为 v3**

17 处中真实缺陷为 5 处（rateBy×3 + mergedGroupId/userId），其余为 v1 粗关联误报；同时 v1 漏报了 itinerary/booking 两处参数传入路径（已人工补修）。为防止「审计清单本身不可信」导致下一轮再漏，脚本重写为 v3 作用域追踪后回归到 0 findings，并把 6 个不可静态追踪点转为「带备忘的警告」而非静默通过。

### 7.5.3 `media_asset` 不随行程软删：**真库已走通**

冒烟 S7 闭环实证：presign → confirm（资产落 `media_asset`）→ DELETE 行程 → 资产行仍在（S7d PASS）。派发单 §1.3 探针未覆盖的路径已由 `real-driver-smoke.cjs` 固化。
