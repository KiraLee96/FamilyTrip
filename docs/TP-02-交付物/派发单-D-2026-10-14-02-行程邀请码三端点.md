// ---- trip 邀请（新增，纯加法） ----

## 一、数据迁移（先做，其他步骤依赖）

新建 `apps/server/prisma/migrations/20261014180000_trip_invite_code/migration.sql`：

```sql
-- AlterTable
ALTER TABLE `trip`
    ADD COLUMN `invite_code` VARCHAR(16) NULL,
    ADD COLUMN `invite_updated_at` DATETIME(3) NULL;

-- CreateIndex
CREATE UNIQUE INDEX `trip_invite_code_deleted_at_key` ON `trip`(`invite_code`, `deleted_at`);
```

口径说明（与 family 域对齐，勿自行发挥）：

1. `invite_code` 允许 NULL：历史行程行与「尚未生成」的行留空；MySQL 唯一索引不约束 NULL，多行 NULL 合法。
2. 唯一索引与 family 完全同构：`(invite_code, deleted_at)`，软删感知。
3. `invite_updated_at` 记录码的最近重置时间；建行程时置 `now`，reset 时更新。**不要**用 `trip.updated_at` 代替——行程内容更新会污染该语义，前端邀请卡展示的「重置时间」会失真。
4. 历史行回填：一次性 `UPDATE` 给存量 trip 生成 8 位码（字符集见 §2.1，查重后写入）。回填脚本随迁移执行或单独数据脚本二选一，在 PR 描述里注明采用了哪种。

## 二、service 层（trip.service.ts）

### 2.1 邀请码生成（抽公共函数，family 域复用）

新建 `apps/server/src/common/invite-code.ts`：

```typescript
/** 邀请码：去掉易混淆字符（0/O/1/I/l），降低口述出错率。与 family 域现有实现同字符集 */
export function randomInviteCode(len = 8): string {
  const alphabet = 'ABCDEFGHJKMNPQRSTUVWXYZ23456789';
  let out = '';
  for (let i = 0; i < len; i += 1) {
    out += alphabet[Math.floor(Math.random() * alphabet.length)];
  }
  return out;
}
```

`family.service.ts` 的私有 `randomCode` 改为委托本函数（行为等价，纯重构；不做也不拦，但两份实现是明确的坏味道）。

### 2.2 create：建行程即生成邀请码

`TripService.create` 的 `tx.db.insert('trip', {...})` 中补两个字段：

```typescript
inviteCode: await this.uniqueTripInviteCode(tx),   // 私有方法，见 2.3
inviteUpdatedAt: now,
```

`uniqueTripInviteCode` 私有方法（对齐 family 的 `uniqueInviteCode`：8 次重试 + 查重 + 失败抛 `INTERNAL_ERROR`）：

```typescript
private async uniqueTripInviteCode(tx: TxHandle): Promise<string> {
  for (let i = 0; i < 8; i += 1) {
    const code = randomInviteCode(8);
    const dup = await tx.db.findUnique('trip', { inviteCode: code, deletedAt: null });
    if (!dup) return code;
  }
  throw new AppError(ErrorCode.INTERNAL_ERROR, '邀请码生成失败，请重试');
}
```

### 2.3 getInvite：取码（含懒生成兜底）

```typescript
async getInvite(userId: bigint, tripId: bigint): Promise<{
  tripId: string; inviteCode: string; updatedAt: string;
}>
```

行为：

1. `findUnique('trip', { id, deletedAt: null })`，不存在 → `NOT_FOUND('资源不存在')`（与全站口径一致，不区分「码无效」与「行程不存在」，防枚举）。
2. 调用方必须是行程成员（复用现有成员判定；非成员 → `FORBIDDEN`）。**外部未加入者看不到邀请码**——码的传播靠组织者复制/分享，不靠接口枚举。
3. `inviteCode` 为空（历史行 / 回填遗漏）→ 懒生成补写并返回，不报错。
4. 返回 `updatedAt = (row.invite_updated_at ?? row.created_at).toISOString()`。

### 2.4 resetInvite：重置（旧码作废）

```typescript
async resetInvite(userId: bigint, tripId: bigint): Promise<{
  tripId: string; inviteCode: string; updatedAt: string;
}>
```

行为：

1. 存在性 + 成员判定同 2.3。
2. **仅主导者或创建者可重置**：复用现有 `assertLeaderOrCreator(tx, t, userId)`（与 `addMember` 同一判定，勿新造）。
3. `inviteCode = await this.uniqueTripInviteCode(tx)`（旧码值被替换即作废，无需显式吊销）。
4. `inviteUpdatedAt = now`；UPDATE 落库。
5. 🔴 不走 CAS：邀请码不属于 E7 版本管辖的行程内容字段，reset 后客户端重新拉取即可；强行传 version 会把「重置邀请码」和「改行程」两个语义搅在一起。family 域重置同样无 version，保持一致。

### 2.5 joinByInvite：凭码加入（幂等）

```typescript
async joinByInvite(userId: bigint, input: {
  inviteCode: string; displayName?: string;
}): Promise<{ trip: Record<string, unknown>; member: Record<string, unknown>; alreadyMember: boolean }>
```

行为（顺序即优先级，勿调换）：

1. `findUnique('trip', { inviteCode, deletedAt: null })`；未命中 → `NOT_FOUND('邀请码无效')`。
2. 幂等：`findUnique('tripMember', { tripId, userId, deletedAt: null })` 命中 → 直接返回 `{ trip, member: existing, alreadyMember: true }`，**不插行、不写 changeLog**。
3. 状态门（GRP-08）：`trip.status` 为 `FINISHED` 或 `CANCELLED` → `FORBIDDEN('行程已结束，无法加入')`。`DRAFT / PLANNED / ONGOING` 放行。
4. 插入 `tripMember`：`userId = 当前用户`、`role = 'MEMBER'`、`isExternal = true`、`accessLevel = 'ACTIVE'`、`displayName = input.displayName ?? 用户昵称`、`managedBy = null`、`joinedAt = now`、`leftAt = null`。
5. 写 `changeLog`（`entityType: 'trip_member'`，`op: 'INSERT'`），与 family.join 同构。
6. 返回 `{ trip: serializeRow(trip, TRIP_BIGINT_FIELDS), member: serializeRow(newMember, MEMBER_BIGINT_FIELDS), alreadyMember: false }`。

并发说明：双请求同时 join 同一码时，应用层查重存在极小窗口双插。与 `addMember` 现有模式一致，**本单不加唯一索引加固**（`trip_member (trip_id, user_id, deleted_at)` 唯一索引涉及全表数据治理，另单评估）。验收以功能幂等为准。

## 三、controller 层（trip.controller.ts）

三条路由，插入位置：成员区（`/trips/:id/members` 之后）与列表区之间均可，保持 `finish → members → join` 可读性：

```typescript
// ── 邀请码：取 ─────────────────────────────────────────
{
  method: 'GET',
  path: '/trips/:id/invite',
  auth: { public: false, resourceType: 'trip', mode: 'READ', ref: tripRef },
  handler: async (ctx) => ({ data: await service.getInvite(ctx.userId!, ctx.resourceId!) }),
},
// ── 邀请码：重置 ───────────────────────────────────────
{
  method: 'POST',
  path: '/trips/:id/invite/reset',
  auth: { public: false, resourceType: 'trip', mode: 'WRITE', ref: tripRef },
  handler: async (ctx) => ({ data: await service.resetInvite(ctx.userId!, ctx.resourceId!) }),
},
// ── 凭码加入（外部同行者；GRP-02）──────────────────────
{
  method: 'POST',
  path: '/trips/join',
  auth: { public: false, resourceType: 'trip', mode: 'WRITE' },
  idParam: '__none__',
  schema: joinTripSchema as never,
  handler: async (ctx, input) => ({ data: await service.joinByInvite(ctx.userId!, input as JoinTripInput) }),
},
```

路由口径：

- `getInvite` 用 `READ`：与 `GET /trips/:id` 同级可见性（成员可读）。
- `resetInvite` 用 `WRITE`：成员可调，主导者判定在 service 内（`assertLeaderOrCreator`），拒时返回 `FORBIDDEN`。
- `joinTrip` 用 `WRITE` + `idParam: '__none__'`：与 `POST /families/join` 完全同构（需登录，但不要求已是家庭成员——加入后才成为成员）。
- 🔴 路径顺序：`/trips/join` 必须与 `/trips/:id` 共存不冲突——`join` 是静态段，现有 dispatcher 已证明该模式可行（families 域同款），如遇匹配问题按 families 域的处理方式对齐，勿改路径。

## 六、验收标准（逐条可测）

### 6.1 功能

1. `POST /trips` 响应体含 `inviteCode`（8 位，`/^[A-HJ-NP-Z2-9]{8}$/`）。
2. `GET /trips/:id/invite` 返回 `{ tripId, inviteCode, updatedAt }`；`tripId` 为字符串。
3. `POST /trips/:id/invite/reset` 返回新码；旧码再 `join` → `404 NOT_FOUND`。
4. `POST /trips/join`（新用户 + 正确码）→ `alreadyMember: false`，`member.isExternal: true`、`role: 'MEMBER'`。
5. 同一用户二次 `join` → `alreadyMember: true`，`tripMember` 行数不变。
6. 错误码 → `404`；`FINISHED` 行程 join → `403` + `行程已结束，无法加入`。
7. 非成员 `GET /trips/:id/invite` → `403`；非主导者 `reset` → `403`。
8. 历史行程（迁移前创建）`GET invite` → 懒生成返回码，不报错。

### 6.2 回归（零破坏）

9. 既有 trip 用例全绿：E7 CAS 冲突（409 VERSION_CONFLICT）、E8 退位三态、B6 结束后只读。
10. `family` 域邀请码行为不变（重构 randomCode 后）。
11. `pnpm typecheck` / `pnpm lint` / `pnpm test` 全过。
