## 二、三处必须处理的语义差异

Prisma 与 `TableDriver` 的契约并非同构，直接透传会出错：

### 1. `update` → 必须用 `updateMany`

`TableDriver.update(where, data)` 的契约是「按**任意条件**批量更新，返回受影响行数」。
而 Prisma 的 `update()` 只接受**唯一选择器**且不接受 `version` 这类普通列。

E7 CAS 乐观锁恰恰依赖 `where = {id, version, deletedAt}` 这种**非唯一**组合 +
「0 行 → 409」判定，所以只有 `updateMany` 满足语义。它返回的 `{count}` 正好就是
`affectedRows`。

### 2. `findUnique` → 必须用 `findFirst`

域代码大量使用 `{familyId, userId, role: 'OWNER', deletedAt: null}` 这类**非唯一组合**
做单行查询——`TableDriver.findUnique` 表达的是「至多取一行」，不是 SQL 唯一约束语义。
Prisma 的 `findUnique()` 会直接拒绝这种选择器。

### 3. `where` 方言 → 显式登记，未知形态一律抛错

若把 `{ OR: [...] }` 当成「名为 OR 的列 = 某值」，查询会**恒空且不报错**；
若把未登记的键透传给 Prisma，Prisma 会**静默忽略**它——条件被丢弃 → 查询范围意外放大
→ **越权读风险**。两种都属静默错值，故一律抛错。

## 三、顺带补全 where 方言（含一处性能缺陷）

排查调用点时发现 `item-sync` 的同步路径存在**全表扫描**：

```ts
await this.o.ctx.read.findMany('changeLog', { where: {} }); // 拉全表，再内存过滤分页
```

客户端只要 ≤100 条变更（`MAX_PAGE_SIZE = 100`），服务端却把**整个 `change_log` 表**
读进内存。设计稿 `ChangeLogReader.fetchAfter` 已明确写了正确的 SQL 下推，但接口**零实现**。

在内存驱动下这个缺陷**不可见**（就一个 Map）。一旦接上真实 MySQL，它会让每次增量同步
都退化成全表扫描 + 全量对象分配——典型的「开发期无感、生产期致命」。

因此把 `Where` 方言从「等值 + IN」扩展为：

- 标量等值（含 `null`）
- 数组 → `IN`
- 操作符对象 `{ gt | gte | lt | lte | in | not }`
- 逻辑组合 `OR` / `AND`（递归）

`MemoryTableDriver.matches` 与 `PrismaTableDriver.toPrismaWhere` **同步实现**，
语义逐条对齐（空 `OR` 恒假、空 `AND` 恒真等）。

> ⚠️ **类型设计取舍**：`Where = Record<string, unknown>` **故意不收窄**值类型。
> 域代码写 `{ tripId: row['tripId'] }`，而 `row[k]` 天然是 `unknown`；收窄会强迫 14 个域
> 到处加类型断言，噪声反而**掩盖**真正的类型问题。保护改由驱动运行期承担——
> **边界处强校验 > 全域弱约束**。

`item-sync` 的下推改造建议单独立项（需同时核对 `buildCursorPredicate` 的调用方），
本轮先把方言与两个驱动的语义一致性做扎实。

## 四、发现并修复的真实缺陷：TDZ 循环依赖

**这是本轮最有价值的修复，因为它只有跑构建产物才暴露。**

`main.ts` 新增 `import { installAppDriver } from './composition-root.js'` 后，
ESM 求值顺序改变，导致：

```
ReferenceError: Cannot access 'APP_TOKEN' before initialization
```

**根因**：`http-adapter.controller.ts` 从 `app.module.ts` import `APP_TOKEN` 常量，
而 `app.module.ts` 又 import 这个 controller —— 循环依赖：

```
app.module  →  http-adapter.controller  →  app.module
```

原求值顺序下这个环「恰好」没炸；新增一条入口 import 就把它点着了。

**修复**：把 `APP_TOKEN` 提到叶子模块 `src/http/app-token.ts`，依赖图变为单向
（controller → token ← app.module，无环）。

> 🔴 **教训**：这类缺陷的特点是 **`tsc` 全过、259 个单测全过**（测试走的是另一条
> import 路径），只在 `node dist/main.js` 时炸。
> **装配层改动必须跑一次真实构建产物**，不能只看 typecheck + 单测。
