## 二、本轮修复的三个「本会静默上线」的架构级缺陷

这三个都是新增集成测试逼出来的真实缺陷，不是测试写错：

### 1. 盲索引（blind index）**永远不可能命中** —— 头号问题

- **现象**：「按订单号查预订」是死代码，永远返回 `{found:false}`。
- **根因**：`computeBlindIndex` 把**主键**混进了摘要，导致同一个业务值在不同行得到不同摘要，`WHERE blind = ?` 天然失配。写入时传真实雪花 ID，查询时传硬编码 `0n`，两边永远不一致。
- **修复**：摘要改为 `sha256(低基数字段… ‖ 被索引值)`，**移除主键**；把明文的订单号贯穿 `computeBlind` / `buildWritePayload` / `findByOrderNo`。同时把 `orderNo` 的 `lowCardinality` 从 `['familyId']` 补全为 `['familyId','tripId']`（规则：所有低基数字段必须参与，否则跨出行会串）。
- **风险等级**：🔴 数据正确性 —— 盲索引是加密字段**唯一**的可检索通道。

### 2. 双语义表被判成私有 → 共享清单「自己勾不了」

- **现象**：`trip_checklist_item` / `checklist_template` 的 `scope=SHARED` 记录，成员访问自己家庭的共享清单项得到 404。
- **根因**：`chain-deps.loadOwnerRef` 把这两张表放进了**私有探测**列表，于是 SHARED 行被私有分支认领并提前返回，**永远拿不到** `familyId` / `tripId`，`checkAccess` 失去 `SHARED_FAMILY` / `SHARED_TRIP` 维度的比对依据。
- **修复**：私有探测只留 `item` / `outfit`；双语义表单独走 `dualProbes`，先读行、按 `scope` 分流 —— `PERSONAL` 走私有短路，`SHARED` 落回共享探测。并给 `ResolvedOwnership` 增加 `scope?` 字段，把域标记原样透传到 `ResourceRef.scope`。

### 3. `assertItemVisible` 类型误转 → 清单读路径全线 500

- **现象**：任何清单读取都 500。
- **根因**：把 `DomainContext`（暴露 `.read`）当成 `TxHandle`（暴露 `.db`）强转，取 `tx.db` 得 `undefined` → `TypeError`。
- **修复**：引入 `driverOf(src)` 归一化函数（`'db' in src ? src.db : src.read`），并把 `assertItemWritable` 的参数类型改为 `TableDriver`。

> 附带修复：`reflect-metadata` 只在 `main.ts` 加载，测试入口不经过它 → 任何 `Reflect.defineMetadata` 直接崩。已加 `test/setup.ts` 并注册到 `vitest.config.ts` 的 `setupFiles`。

## 三、本轮工程化改动

### 新增 `common/db/row-key.ts` —— 行值归一化的唯一出口

起因是 ESLint 报出 **32 处 `no-base-to-string`**。这**不是**风格问题：`Row = Record<string, unknown>` 让 `row[k]` 天然是 `unknown`，随手写 `` `${row[k]}` `` 对对象会走 `Object.prototype.toString` 得到 `"[object Object]"` —— 编译期不报错、运行期静默错值。在「审计日志拼接 / 盲索引计算 / 唯一键组装」里出现，后果是**不同行被判成同一行**。

提供的 API（**只有这个文件允许把 unknown 转 string**）：

- `toKeyString(value, ctx)` —— 严格模式，用于身份归一化；遇到 object / symbol / function **直接抛错**（宁可炸在写入点，也不产出毒值落库）
- `toDisplayString(value)` —— 宽松模式，**仅用于日志**，对复杂类型返回可读摘要而非 `[object Object]`
- `rowKeyOf(row, keyField='id')` —— 取主键
- `stringCell(row, field)` / `bigIntCell(row, field)` / `bigIntCellOrNull(...)` —— 类型化单元格读取

已把 32 处调用点全部改为经此出口，覆盖 `table-client` / `chain-deps` / `checklist` / `expense` / `fx` / `holiday` / `memory` / `notify` / `wish` 九个文件。

### 测试脚手架去重 → `test/helpers.ts`

4 个集成测试文件各自复制了一份 `req` / `mustOk` / `dumpTable` / `scaffold`（`scaffold` 只差出行日期）。已抽成共享模块，新增 `Scaffold` / `DispatchResult` 显式接口。

### `vitest.config.ts` 改为单线程池

**这不是绕过问题，是修一个真实的环境缺陷。**原配置下 Windows 上 vitest 的默认 worker 池会调用 `wmic.exe` 探测 CPU；在受限/沙箱环境里该调用失败，并连带把**尚未收集完的 2 个测试文件静默丢弃**——表现极具迷惑性：「跑了 137 个用例全绿」，实际少了 44 个。

修复后：`pool: 'threads'` + `singleThread: true`，并关闭 SSR 转译缓存的落盘（临时目录写入在受限环境会 EPERM）。副作用是**更快**：5.15s → 2.19s。

## 五、关键设计约束（供后续接手者）

- **时间唯一来源**：`dbNow()`。业务写路径禁止 `new Date()`，否则同步游标会被撕裂。
- **软删唯一键**：所有业务表带 `deletedAt`，唯一键是 `(业务键…, deletedAt)` 复合。
- **404 不可区分（D8）**：`notFoundIndistinguishable()` 是唯一 404 出口；越权与不存在**逐字节一致**。
- **PRIVATE 短路（D4）**：`owner_id = U OR managed_by = U`，**绝不**回落家庭/出行维度。
- **CAS（E7）**：`version` 列 + 影响行数判定；0 行 → 409 / 4090（`VERSION_CONFLICT`）。
- **同步游标（E1–E6）**：`(changedAt, id)` 复合游标，严格 `>` 语义，同毫秒不漏单。
- **红线**：R1 `toBuffer()` 纪律（ESLint 有 `no-restricted-syntax` 语法层封堵）；R3 盲索引同事务；R4 AAD 含表标识；R5 仅 `SPOT_SELL`；R6 切档位不重算历史；R7 禁止抓取汇率（生产 fail-fast）。
