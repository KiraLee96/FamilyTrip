### 4.6 迁移：`prisma/migrations/20261105000000_media_asset_family_nullable/migration.sql`

```sql
ALTER TABLE `media_asset` DROP FOREIGN KEY `media_asset_family_id_fkey`;
ALTER TABLE `media_asset` MODIFY `family_id` BIGINT NULL;
ALTER TABLE `media_asset` ADD CONSTRAINT `media_asset_family_id_fkey`
  FOREIGN KEY (`family_id`) REFERENCES `family`(`id`)
  ON DELETE SET NULL ON UPDATE CASCADE;
```

> SQL 由 `prisma migrate diff --from-schema-datamodel <旧> --to-schema-datamodel <新> --script`
> 原样生成。外键必须 DROP+ADD：可选关系的 Prisma 默认引用动作是 `SET NULL`，
> 只 MODIFY 列会让库与 schema 漂移。

## 五、③ 与 ⑤ 为何不改代码

- **③**：`resolveMediaStorage()` 已在生产缺 `MEDIA_PUBLIC_BASE_URL` / `MEDIA_UPLOAD_SECRET`（或仍是占位域名）时返回 `UnconfiguredStorage`，`presign` 抛 `MEDIA_STORAGE_UNCONFIGURED(5008)` → HTTP 503，**服务照常启动**。`OBJECT_STORAGE_PROVIDER != local` 直接抛错。派发单要求的行为与现状一致，故不动代码，只补验收（`test/media-upload-roundtrip.test.ts` ①②）+ 更新 `docs/媒体存储接入.md`。
- **⑤**：`GET /auth/me` → `data.user`、`PATCH /auth/me` → `data.user + updatedAt`（`meta.updatedAt` 同值），昵称直写 `user.nickname` 并从库读回。派发单的结论本身就是「后端契约已正确」，改动风险大于收益，**保持原样**。
