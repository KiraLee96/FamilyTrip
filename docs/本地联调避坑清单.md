# FamilyTrip 本地联调避坑清单

> 沉淀自 2026-10-26 ~ 10-27 的真实联调过程。**每条都踩过、都有后果**，不是理论。
> 用法：开工前扫一遍 A 区，改代码时看 B/C 区，验收时看 D 区，报错时查 E 区。
> 维护规则：踩到新坑就追加到这里，并注明「现象 → 根因 → 动作」，别只写结论。

---

## A. 开工前：环境（最容易浪费时间的一区）

| #   | 坑                                | 现象                                                | 动作                                                                                                                |
| --- | --------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| A1  | **服务不能交给助手长期托管**      | 测到一半突然 `ERR_CONNECTION_REFUSED`，之前一切正常 | 双击 `start-dev.cmd` 自己起。助手起的进程挂在沙箱会话里，闲置即被回收（已发生 5 次）                                |
| A2  | **助手起的进程你杀不掉**          | `taskkill /PID xxx /F` → `拒绝访问`                 | 别自己杀。让助手先停，3000 空闲后再双击脚本                                                                         |
| A3  | **端口被占导致新进程静默退出**    | 日志 `EADDRINUSE: address already in use :::3000`   | 脚本已改：会打印占用 PID 并尝试接管；失败时明确提示「请让助手停掉」                                                 |
| A4  | **MySQL 冷启动比后端慢**          | 后端日志刷 `Can't reach database server`            | 脚本已改为轮询 3306 到真就绪（最多 25s），不再死等 6 秒                                                             |
| A5  | **局域网 IP 会变**                | 真机突然连不上                                      | 换网络后先查 IP 再重编：`set API_BASE_URL=http://<新IP>:3000/api`                                                   |
| A6  | **手机上的 127.0.0.1 是手机自己** | 模拟器能连、真机不能                                | 真机/局域网必须用电脑 IP（如 `10.23.30.90`）                                                                        |
| A7  | **域名校验被私有配置覆盖**        | `不在以下 request 合法域名列表中`                   | 查 `project.private.config.json`（优先级高于 `project.config.json`），`urlCheck` 必须是 `false`；改完**要重开项目** |

## B. 数据源：Mock 的"全绿"不能当功能可用

| #   | 坑                                | 现象                                  | 动作                                                                                               |
| --- | --------------------------------- | ------------------------------------- | -------------------------------------------------------------------------------------------------- |
| B1  | **不注 `API_BASE_URL` 就是 Mock** | 一切正常，但从来没连过后端            | `api/index.ts`：`DATA_SOURCE = hasBackend ? 'http' : 'mock'`。验收必须注入 `API_BASE_URL` 打真后端 |
| B2  | **Mock 会跳过上传**               | 上传"成功"但图片打不开                | Mock 的 `uploadUrl` 为空，`Taro.uploadFile` 那段被 `if (presign.uploadUrl)` 跳过                   |
| B3  | **Mock 直接改内存对象**           | 字段校验、schema strip 类问题全被掩盖 | 改资料/上传类改动，必须真后端验一遍                                                                |
| B4  | **H5 无头验收跑 Mock 会假成功**   | 报告 19/19 PASS，实际链路一条没通     | 无头验收的构建也要注入 `API_BASE_URL`                                                              |

> 结论：**Mock 全绿只证明界面能渲染，不证明业务能用。** 这两件事必须分开说。

## C. 数据库：本地库落后于代码，是所有"莫名 500"的头号来源

| #   | 坑                                 | 现象                                                                     | 动作                                                                                                                             |
| --- | ---------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| C1  | **schema 落后**                    | 登录 500，日志 `The column 'xxx' does not exist in the current database` | `cd apps/server && npx prisma db push`。看到 `does not exist` 就先想 schema，别怀疑业务代码                                      |
| C2  | **"看起来空"不等于空**             | 以为能随便重建，其实有数据                                               | 重建前逐表 `count(*)`，别只看列表。`select count(*) from 每张表`                                                                 |
| C3  | **子查询里裸表名**                 | `ERROR 1046 (3D000): No database selected`                               | SQL 脚本开头必须 `USE family_trip;`                                                                                              |
| C4  | **列名驼峰/下划线混用**            | `Unknown column 'u.avatar_url'`                                          | `avatarUrl`、`nickname` 无 `@map` 用驼峰；`home_timezone`、`created_at` 有 `@map` 用下划线。**先查 information_schema 再写 SQL** |
| C5  | **软删列不是每张表都有**           | 批量 UPDATE 半途失败                                                     | 先查：`trip_invite`、`checklist_item` 就没有 `deleted_at`，只能随父级不可见                                                      |
| C6  | **Prisma Json 列裸 null 是可以的** | ——                                                                       | 我用「生成类型不接受」推断「运行时会拒」，被实验推翻。**类型不接受 ≠ 运行时拒绝**，别拿类型当运行时判据                          |

## D. 身份：开发桩会让"每次登录都换人"

| #   | 坑                                  | 现象                                         | 动作                                                                                                       |
| --- | ----------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| D1  | **`openid_${code}` 每次都是新用户** | 改完昵称重登就没了、列表全空、页面像"打不开" | `.env` 配 `DEV_WECHAT_OPENID=<固定 openid>`，桩就恒定返回它                                                |
| D2  | **切 openid 等于换账号**            | 数据"忽隐忽现"                               | 改之前**先查库里真实账号**（`select openid,nickname from user`），别拍脑袋给名字                           |
| D3  | **旧 token 指向旧用户**             | 改完身份但看到的还是旧数据                   | 必须清缓存。JWT 里编码的是 userId，secret 不变则旧 token 依然有效                                          |
| D4  | **Console 里的 401 可能是自愈过程** | 报 401 但界面数据正常                        | 客户端有 4010 → 清 token → 单航班重登 → 重试一次 的兜底。判断标准是**界面有没有数据**，不是有没有 401 日志 |

## E. 前端 / 构建

| #   | 坑                                  | 现象                                                              | 动作                                                                                                                                                           |
| --- | ----------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1  | **Taro 双平台不能并行构建**         | 7 分钟无输出后挂住，报 `@tarojs/service platform.ts` 栈错         | 串行跑：先 weapp 再 h5                                                                                                                                         |
| E2  | **构建被沙箱防批量删除拦截**        | "构建好像跑完了但 dist 没变"                                      | `CODEBUDDY_SAFE_DELETE_ENABLED=0 npx taro build --type weapp`                                                                                                  |
| E3  | **`cmd \| tail` 吃掉退出码**        | 构建失败被当成功                                                  | `set -o pipefail` + `echo ${PIPESTATUS[0]}`                                                                                                                    |
| E4  | **Taro H5 `<Canvas>` 不是 canvas**  | `d.getContext is not a function`                                  | 渲染成 `<taro-canvas-core>`，内部 canvas **异步挂载** → 轮询 `host.querySelector('canvas')`                                                                    |
| E5  | **H5 canvas 别自己算缩放**          | 右侧被裁、文字出界                                                | canvas 绘制尺寸由 `width/height` **属性**决定，显示尺寸由 CSS 决定 → 属性给 750×H，样式给 `width:100%;height:auto`。改完属性要显式设 style，否则按 1500px 撑爆 |
| E6  | **预览别渲染两份**                  | 用户看到"两张一模一样的图"，像 bug                                | canvas 本身就是预览，别再加 `<Image src={dataURL}>`                                                                                                            |
| E7  | **`useDidShow` 只能用在页面组件**   | 子组件里无效或报错                                                | 子组件要刷新用别的机制（父级触发 / props）                                                                                                                     |
| E8  | **`Link` 是 navigateTo（压栈）**    | 详情↔管理来回点几次后 `routeDone with a webviewId N is not found` | 返回语义用 `backOr()`（退栈，无上一页才 redirect）；页面栈上限 10 层                                                                                           |
| E9  | **Taro H5 会保留旧页面 DOM**        | `document.body.innerText` 混入别的页面文案                        | 断言/取文本要限定在容器内（`querySelector('.sheet-root')`）                                                                                                    |
| E10 | **Taro modal 在 `.taro_page` 之外** | 页面作用域里点不到弹窗按钮                                        | 弹窗按钮要 document 级查询，类名是 `taro-modal__btn` / `taro-model__confirm`（少个 a 是官方的）                                                                |
| E11 | **纯函数住在组件文件里就测不了**    | vitest 报 `ENABLE_INNER_HTML is not defined`                      | 组件文件 import 了 `@tarojs/components`。纯逻辑放 `utils/`，组件里 re-export                                                                                   |

## F. `.cmd` 脚本（Windows）

| #   | 规则                                | 原因                                              |
| --- | ----------------------------------- | ------------------------------------------------- |
| F1  | **绝不能有非 ASCII 字符**           | cmd 按 GBK 解释，中文注释会变乱码甚至引发语法错   |
| F2  | **必须 CRLF 换行**                  | LF-only 下标签/goto 行为不稳                      |
| F3  | **避免多行括号块**                  | 用 `goto :label` 代替 `if ... ( ... )` 多行体，稳 |
| F4  | **路径含空格用 `start /D "<dir>"`** | 别 `cd /d` 再 start，引号会打架                   |
| F5  | **写完校验字节**                    | `node -e "检查 buffer 里有无 >127 的字节"`        |

## G. 测试与验收写法

| #   | 坑                                    | 现象                                                                 | 动作                                                                              |
| --- | ------------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| G1  | **`Object.assign` 复制的是值**        | 计数器断言恒为 0，测试假失败                                         | 用 `Object.defineProperty(obj,'n',{get:()=>count})`                               |
| G2  | **断言别查文案关键词**                | 查「邀请码」结果命中自己写的提示语「不含邀请码」                     | 断言查数据/元素结构/业务动作，不查自然语言                                        |
| G3  | **服务端测试要在 `apps/server` 下跑** | 根目录跑报 `Reflect.defineMetadata is not a function`（假失败 3 条） | 那里才有 `vitest.config.ts` 的 setupFiles（加载 reflect-metadata）                |
| G4  | **验收要能反证"真的画了/真的写了"**   | 只看"没报错"会漏                                                     | 例：长图用 `canvas.toDataURL().length > 5000` 反证像素非空，而不是数 `<img>` 节点 |
| G5  | **一次只验一条**                      | 攒 6 条一起验，出错分不清是谁                                        | 单条改完 → 双端构建 → 真后端验 → 再下一条                                         |

## H. 后端改动须知（前端视角的红线）

| #   | 事实                                                                | 含义                                                                                                            |
| --- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| H1  | `signUpload` / `putObject` / `fetchObject` 是**可注入口**，不是实现 | 未注入就返回占位地址 `https://upload.local/...`，上传必失败。2026-10-27 已由 local-disk 驱动补上                |
| H2  | `Taro.uploadFile` 只能发 **multipart POST**，不能 PUT 裸流          | 小程序端没有 fetch/Blob。「presign 一个 PUT URL 让客户端 PUT」这条路走不通                                      |
| H3  | Zod 默认 **strip 未知键**                                           | schema 少一个字段 = 静默丢弃 + 接口回 `code:0` + 库里 NULL。**"接口成功"不等于"数据写进去了"**                  |
| H4  | 契约补齐 ≠ 改签名                                                   | `UpdateProfileInput.avatarUrl` 前端早就定义了，后端漏实现 —— 这种补齐不需要前后端同步会议，但不能因此随便改签名 |
| H5  | `assertTripMediaWritable` 与其它域的写门是**分开的**                | 归档后「照片可写、安排/清单/花销不可写」是刻意设计，不要一刀切                                                  |

## 快速自检（每轮开工 30 秒）

```
1. 双击 start-dev.cmd          → 两个窗口起来，health 返回 200
2. 确认身份                   → 登录返回的 openid 是你预期的那一个
3. 确认数据源                 → 构建时注入了 API_BASE_URL（不是 Mock）
4. 端口/ip 未变              → 真机用的是当前局域网 IP
5. 想清「这一轮要验的是界面还是链路」→ 决定用 Mock 还是真后端
```
