### 🔴 B1.4 为什么是硬阻塞

风险 **R-2**：Prisma 对 `VARBINARY` 与自定义类型转换器的支持未验证，**直接阻塞 A1 表结构落地**。若不支持，须改 TypeORM 或手写 Repository —— **这个决定必须在编码前做出**，不能等到解密静默失败才发现。

**判别标准（照抄 M2 的坑）**：

```js
// ✅ 正确：Prisma 从 MySQL 读回 VARBINARY 是裸 Uint8Array，必须先转 Buffer
const plain = decipher.update(toBuffer(rt), undefined, undefined);
// ❌ 禁止：Buffer.isBuffer(Uint8Array) === false → 直接传会静默失败
```

**报告需回答 3 个问题**：

1. Prisma 能否 `create` 写入 `VARBINARY(1024)` 并原样读回？（往返一致）
2. 读回类型是 `Uint8Array` 还是 `Buffer`？是否需 `toBuffer()` 适配层？
3. 若不可行，替代方案是 TypeORM 还是手写 Repository？给出结论 + 证据

### 🔴 硬约束

1. **不改后端业务代码**（只做环境 + 验证）
2. **M1 存储层级**：生产配置 `STANDARD` 常驻，**⛔ 不配置归档生命周期规则**
